# 定位并修复：面板「立即升级」点击后卡住

## 用户报告（2026-10-19）

「这地方如果有更新会有一个立即升级按钮，不过点了之后会卡住，只能等容器刷新后就没有了，先定位你去解决一下」

## 定位方向（只读）

1. 前端 `applyUpdate()`（`maintenance/update-api.ts`）的请求是否有**超时**；`handleConfirmUpdate` 的 `applying` 状态在请求不返回时是否永远 true；
2. 后端 apply 处理（`service/update_apply.go` + controller）：是否**先写响应再 exec 重启**，还是重启打断了响应（导致客户端挂起/连接重置）；
3. 既然本轮 v0.0.23 已加"ok 后轮询并自动刷新"，为什么没生效 —— 是否因为 `result.ok` 永远拿不到（请求不返回）。

## 目标

- 点击后**不卡**：请求要有明确超时；超时/连接重置时**乐观启动重启轮询**（等服务恢复→自动刷新；90s 未成功→提示手动刷新）；
- 失败路径（busy/not_newer/下载/校验失败）仍要**如实报错且不刷新**；
- 不引入重复刷新（沿用按版本的一次性守卫）。

## Acceptance Criteria

- [ ] 用代码行号说明卡住的根因（前端/后端各一条）
- [ ] 修复后：点击→（有响应则按现状处理；无响应/超时→进入轮询→自动刷新）
- [ ] 测试覆盖"请求超时/连接错误 → 仍进入 watch"与失败 reason 不刷新
- [ ] 七条门全绿；发版并真机验证

## 用户更正（2026-10-19，以此为准）

「错了，是能升级，就是**弹窗有点问题**，点击更新 → 弹窗 → 等一会消失 → 刷新。」

⇒ **不是卡住** ✗。真实流程：升级本身成功、页面也自动刷新了 ✓；
问题在**对话框**：点"更新"后确认弹窗**立刻关闭** ✗ → 中间的"重启中"进度**无处可见** ✗ →
过几秒页面突然刷新 ✗（用户感知为"弹窗一闪就消失，然后页面莫名刷新"）。

### 代码依据（Lead 已定位）

`update-checker-section.tsx` 的 `handleConfirmUpdate()`：

```ts
if (result.ok) {
  setConfirmOpen(false)     // ← 立刻关弹窗
  ...phase='restarting'     // ← 进度提示渲染在"页面里"，而弹窗已经关了
```

⇒ 用户看不到进度，只看到弹窗消失 + 随后刷新。

### 修复方向

- **弹窗保持打开**直到流程结束：`ok` 后不关弹窗，改为在对话框内展示"正在重启…（最长 90 秒）"的进度态；
- 自动刷新成功前**不**关弹窗；刷新后页面整体换新（弹窗随页面消失，天然收尾）；
- 90 秒超时 → 弹窗内改成"更新可能已完成，请手动刷新" + 可关闭按钮（不刷新）；
- 失败路径（busy/not_newer/下载/校验失败）→ 弹窗保持打开并显示错误（现状已如此，别退化）；
- 保持既有：只对 `ok` 启动轮询、按版本一次性守卫、避免重复刷新。

## 修复结果（2026-10-19，v0.0.28）

按用户更正后的症状（**能升级、弹窗一闪就消失**）修复：

- `ok` 分支**删除** `setConfirmOpen(false)` → 弹窗保持打开并进入 `restarting` 态；
- 弹窗三态：`idle`（Update now / Cancel）→ `restarting`（标题「Restarting the service…」+ 进度说明 + 两按钮 disabled + `onOpenChange` 拒绝 Esc/遮罩关闭）→ `timed-out`（「Update may be complete / 请手动刷新」+ Close 只关弹窗不刷新）；
- 成功由 watcher `window.location.reload()`，弹窗随整页消失；
- 页面常驻提示只保留**超时**一种（避免与弹窗内进度重复）；
- 新增 4 条 i18n 键（7 语言）；组件测试 +2（成功不关弹窗且按钮 disabled、超时关闭不刷新、失败不进入 watch）→ `bun test` 339 → **341**；七条门全绿。

### 验证方式

实例升级到 v0.0.28 后，**下一个版本发布时**从面板点「立即升级」即可看到新行为：
点更新 → 弹窗**不消失**，显示"正在重启…"且按钮变灰 → 几秒后整页刷新。
