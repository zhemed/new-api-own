# 项目维护：清理陈旧内容并同步文档

## 用户授权

「你去把项目维护一下该删除的删，该更新的更新」——授权本轮做删除与更新。

## 范围

1. 查清上轮遗留：粗 grep 命中 4 个含 `compose`/`.service` 字样的路径到底是什么；
2. 归档 9 月遗留的未归档任务（`.trellis/tasks/` 下的非 archive 目录）；
3. 文档与配置同步：弱盘日志新环境变量（`LOG_SQL_DSN=memory` / `LOG_CLEANUP_*` / `LOG_MEMORY_MAX_ROWS`）写进 `.env.example`；发布流程说明与 CI 实际触发面（Release/Electron/GitCode 手动触发）一致；
4. 敏感信息扫描：仓库内是否残留内网地址/域名/密钥（只报告文件与数量，不复述内容）；
5. 其他陈旧内容：过期版本号引用、失效路径引用、构建/部署文档与实际不符处。

## 边界

- 只动仓库内文件；不碰生产、不碰本机演示实例（用户已决定继续运行）。
- 任何删除都要在 PRD 里留痕（删了什么、为什么）。

## Acceptance Criteria

- [ ] 4 个遗留路径逐条定性
- [ ] 未归档任务处理完毕
- [ ] `.env.example` 等文档与当前功能/流程一致
- [ ] 敏感信息扫描有结论（命中则列出文件，不落内容）
- [ ] 门禁（guard + make test）通过，提交推送
