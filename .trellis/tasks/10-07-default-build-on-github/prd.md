# 把 README 部署命令替换为当前的日志内存模式

## 用户指示（2026-10-07）

「就是[把这一行]替换成我们现在的日志内存模式就好了，其他的不要动」
（原始诉求："我们现在的部署方式推送到GitHub做默认的构建方式"）

**不是**改 CI：当前 CI 只在版本 tag 上构建镜像与 Release（保持不变）；
**只是**把 README 的首选部署命令换成实例正在用的内存日志参数，并推送到 GitHub。

## 实际改动（仅 README.md 部署命令一处）

在部署命令中补上与实例完全一致的四条环境变量：

```
-e LOG_SQL_DSN=memory -e LOG_MEMORY_MAX_BYTES=200MB
-e LOG_MEMORY_MAX_ROWS=200000 -e LOG_CLEANUP_RETENTION_DAYS=7
```

并新增一条说明：这是当前在用的日志模式（内存、200MB 上限、保留 7 天、写入时按字节裁剪、无定时清理；
日志重启即丢；去掉 `LOG_SQL_DSN=memory` 即回落盘）。

## 未改动（用户明确要求"其他的不要动"）

- CI 工作流（docker-build / release 的触发条件与产物）—— 保持不变；
- `README.en.md`、`MAINTENANCE.md` 中的部署/升级/回滚命令 —— 保持原样（未同步）；
- 代码。

## 已知的后续风险（已向用户提出）

升级/回滚命令里**没有**这四条环境变量：照那些命令重建容器会**丢掉内存日志模式**（回落盘）。
需要时再同步（用户未授权本轮改动）。
