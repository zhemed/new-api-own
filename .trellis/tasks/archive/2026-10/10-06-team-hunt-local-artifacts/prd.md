# 排查本机旧版本残留（复用编制）

## Goal

只读排查本机（及本会话可合法访问的范围）是否还存在**旧版本（尤其 0.5）的 new-api 来源**——
运行中的进程/容器、已构建镜像、文件系统里的可执行文件与静态目录——并给出「用户是否可能看到 0.5」的明确结论。

## Requirements

1. **进程与端口**：`ss -ltnp` 全量监听 + `ps -eo pid,etime,cmd` 全量进程，按**可执行路径/端口**而非名字筛
   new-api 类进程；对每个命中确认版本：`/proc/<pid>/exe` 指向的二进制、启动时间、监听端口，
   必要时只读查询 `http://127.0.0.1:<port>/api/status`。
2. **Docker**：`docker ps -a`、`docker images -a`（含 `<none>` dangling）、`docker volume ls`；
   是否存在 0.5 相关容器/镜像/卷；注意 docker 环境标准为 29.7.2 + compose v5.4.0，先只读核对版本。
3. **文件系统**：工作区内（`.local-instance/`、`data/`、构建产物等）及允许访问的路径中，
   找 new-api 可执行文件 / 静态目录，记录大小、mtime、版本；只列不碰。
4. **结论**：本机是否存在"用户可能看到 0.5"的来源（旧进程 / 旧静态目录 / 旧浏览器标签等）。

## Constraints

- **只读**：禁止删除、停止、重启任何进程 / 容器 / 镜像 / 数据；不 `docker prune/rm/stop`。
- 不读写工作区外私有配置（`~/.ssh`、`~/.dsh` 等）；不读 `/var/log`；无外部网络动作。
- 禁止 `git add -A`、禁止在仓库内建 git worktree、禁止 commit/push。
- 不触碰 `.local-instance/`（只列）。

## Acceptance Criteria

- [ ] 进程/端口清单：每项含 PID、端口、可执行路径、启动时长、版本判定依据。
- [ ] Docker 清单：容器（含已停止）、镜像（含 dangling）、卷；明确有无 0.5。
- [ ] 文件系统清单：路径 + 大小 + mtime + 版本判定。
- [ ] 明确结论："本机有没有 0.5"（含证据强度与无法验证项）。
- [ ] 汇报 ≤20 行、结论先行、中文。
