# 前端：版本/更新状态 UI（抄 komari 在线更新逻辑）

## Goal

让「版本 / 更新」在面板上**看得懂、说得准**：系统维护页的更新卡片明确展示
**当前版本 / 最新版本 / 是否有更新**，三态语义正确、失败降级为中性 `unknown`，
且前端**不直连** `api.github.com`（等后端字段）。

背景：生产截图为"有新版本可用：v0.0.5"（比当前版本还旧），根因是更新源错 + 比较逻辑曾严格比较。
`version-compare.ts` 已修为 unknown 中性显示；本任务补齐 UI。

## Requirements

### R1 更新卡片展示三件事
在「系统维护」页的更新卡片上分别展示：
1. **当前版本** —— 来自 `/api/status`
2. **最新版本** —— 无数据时显示"未知"，**不得外呼**
3. **是否有更新** —— 按比较结果给三/四态文案

### R2 四态文案（与 `version-compare.ts` 结果对齐）
| 比较结果 | 展示 |
|---|---|
| `equal`（相等） | 「已是最新」 |
| `older`（远端更旧） | 「已是最新」（**绝不**提示"有新版本"） |
| `newer`（远端更新） | 「有新版本可用：vX.Y.Z」 |
| `unknown`（无法判定） | 中性文案，不暗示有/无更新 |

### R3 不引入任何浏览器外呼；失败降级 unknown
- 前端**不得**访问 `api.github.com` 或任何第三方更新源。
- 后端字段未到位前：**保留现有行为**，但把失败/缺失降级为 `unknown`
  —— 不报错、不弹"有新版本"。
- 预留**单一接入点**（如 `useLatestVersion()` 小封装），后端字段一到即接。

### R4 无数据源时的替代方案（手动核对）
展示当前版本 + 一行"如何升级"文案（指向 README 的升级三步）。
**不得**在仓库写入任何主机名/内网地址。

### R5 不重复造版本显示点
顶部品牌药丸已显示版本；新 UI 与之一致，不新增第二个版本显示点。

### R6 质量门
收工前 `bun run typecheck | lint | test | build | knip | i18n:check` 全绿。
新增文案必须走临时 `scripts/add-missing-keys.mjs` + `bun run i18n:sync`，**禁止手改 `locales/*.json`**；
若新增常量中的键无法被 `t('...')` 字面量扫描到，须登记进 `src/i18n/static-keys.ts` 的 `STATIC_I18N_KEYS`
（`i18n:check` 会合并该表逐语言校验）。

## Constraints

- 只改 `web/**`；不 commit / push；不新增依赖；不引入浏览器外呼；不动 3020。
- 证据需可复核（文件:行）；不确定标"待确认"。
- 环境事实以实测为准（先确认 `bun` 与 `web/node_modules` 是否可用）。

## Acceptance Criteria

- [ ] AC1：更新卡片同时展示当前版本、最新版本、更新状态三项，四态文案符合 R2。
- [ ] AC2：全仓 `web/src` 内无 `api.github.com` / 无第三方更新源外呼（可 grep 复核）。
- [ ] AC3：失败/字段缺失 → `unknown` 中性展示，控制台/界面无报错、无"有新版本"误报。
- [ ] AC4：存在单一接入点 `useLatestVersion()`（或等价封装），后端字段到位后只需改一处。
- [ ] AC5：无数据源时展示"如何升级"文案，且仓库内无主机名。
- [ ] AC6：不新增第二个版本显示点（顶部药丸保持唯一品牌版本位）。
- [ ] AC7：六条命令全绿（或明确列出无法运行项 + 原因 + 替代验证）。
- [ ] AC8：新增文案七语言齐备，`i18n:check` 通过；locale 改动走脚本（临时脚本用后删除）。

### 范围变更记录（按时间顺序，均已落地）

1. **首轮**：三态显示 + 不得直连 `api.github.com` + 等后端字段。
2. **二轮（Lead 定调）**：保留既有 GitHub 直连、不新增外呼、不引入自动更新那套下载/替换/重启；
   后端服务端检查一度叫停 → 按"当前即最终"收尾。
3. **三轮（最终）**：后端已交付并可自更新 → 改为
   - 数据源 = `GET /api/status/update`（服务端检查，AdminAuth）；**浏览器直连 GitHub 已删除**
     （理由：状态「检查被管理员关闭」要求遵守 `UPDATE_CHECK_ENABLED`，浏览器侧直连无法被该开关约束）；
   - 新增管理员「立即更新」+ 二次确认（重启 / 容器重建退回镜像两条代价）+ 执行中 + 失败可读原因；
   - 四态：有更新 / 已最新 / 无法确定 / **检查已关闭**（后者与"无法确定"必须区分）；
   - `POST /api/status/update/apply`；`apply_enabled` 因不在状态响应内，暂读 `/api/option/` 的
     `update_check_setting.apply_enabled`（已在 findings.md 向 Lead 提出后端补字段以移除该绕道）。
