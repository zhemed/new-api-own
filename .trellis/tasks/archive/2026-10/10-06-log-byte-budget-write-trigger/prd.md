# 改造日志上限：写入触发 + 字节预算（去掉定时器）

## 用户诉求（2026-10-06）

1. 上限想按**体积**表达（200MB），而不是行数；
2. **不要 5 分钟定时清理**；
3. 「还有什么好办法」→ 选定方案：**写入触发 + 字节预算**。

## 设计（Lead 定稿，实现照此）

### 配置语义

| 环境变量 | 语义 | 默认 |
|---|---|---|
| `LOG_MEMORY_MAX_BYTES`（**新增**）| 日志**载荷字节**预算，接受 `200MB`/`209715200` 形式；0/未设=关闭 | 未设为关闭；文档建议 200MB |
| `LOG_MEMORY_MAX_ROWS`（已有）| 行数上限（次级约束，与字节预算同时生效）| 内存模式 20 万 |
| `LOG_CLEANUP_INTERVAL`（已有）| 定时清理间隔 | **配置了字节预算时默认 0（关闭）**；显式设置仍生效 |
| `LOG_CLEANUP_RETENTION_DAYS`（已有）| 按天保留 | 7（在写入触发路径里执行）|

### 机制

1. 进程内 **atomic 字节计数**（载荷估算：文本字段 `len` 之和 + 固定开销），启动后首次使用时用一次 `SUM(length(...))` 校准；
2. 每次写入日志后累加（O(1)，**不得**阻塞请求路径）；
3. 超过预算 → 触发**异步、单飞（single-flight）**裁剪：分批删除最老记录，直到回到预算内；同一遍顺带执行保留天数删除；
4. 保证：不删到空表以下（单行超预算时保留最新一行即可）；并发只有一路；失败不影响写日志主流程，只记日志。
