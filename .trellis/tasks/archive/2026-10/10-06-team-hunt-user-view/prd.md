# 用户视角找漏（复用编制）

## Goal

从**用户视角**（打开面板、用这套网关）找出至今未被发现的**真实缺陷**，并把"新版本可见性"缺口
落成 `web/**` 内的修改或明文结论。

## Requirements

### 一、用户视角问题清单（每条必须可复现 / 有证据）

1. **用户怎么知道有新版本**
   - 用 `bw`（本机常驻无头浏览器）打开本机 **3020** 面板，实际记录用户能看到什么
     （页脚 / 关于页 / 系统信息页），给结论：用户如何得知自己落后一个版本。
   - 查清前端是否已有版本展示、是否有任何"检查更新"入口（`web/**` 内取证）。
2. **界面与后端实际状态是否一致**
   - 用只读接口（`/api/status` 等）对照面板显示：版本、数据库状态、计费概览等。
3. **自选 2-3 个高频页面**（候选：Key 管理 / 日志 / 模型 / 渠道）
   - 找**功能性**缺陷（不是风格问题），每条给**复现步骤**。

### 二、落成修改（`web/**`）

- "更新提示"若**该做且可控**：实现最小可用版本 + 补测试（`bun test`）。
  - **不得引入网络请求、不得新增依赖**；必须**由后端字段驱动**或**纯本地展示**
    （前端绝不主动外呼）。
- 若**不该做**：写清理由。
- **若必须改 Go 后端才能实现 → 停下来报告**，交 Lead 指派后端成员，不得擅自改 Go。

## Constraints

- 无外部网络访问（**仅**允许本机 3020 与 ghcr 只读查询）；不改 Go 代码；不 commit/push/tag；
  不动用户远程实例；禁止 `git add -A` 与建 git worktree；只改 `web/**`；不动 `.local-instance/`、
  不重启任何服务。
- 收工前 `bun run typecheck`、`bun run lint`、`bun test`、`bun run build` 必须全绿（贴输出）。

## Acceptance Criteria

- [ ] 交付一：用户视角问题清单，每条含复现步骤或证据（文件:行 / 接口返回 / 浏览器实测记录）。
- [ ] 交付一：3020 面板"版本可见性"的实测结论（页脚/关于/系统信息页截图或文本记录）。
- [ ] 交付一：面板显示与 `/api/status` 的对照结论，指出任何不一致。
- [ ] 交付二：更新提示要么已实现（含测试）并说明驱动来源，要么写明"不做"的理由，
      要么明确"需要后端改动"并停下报告。
- [ ] 四条命令实测输出（含退出码），全部 exit 0。
