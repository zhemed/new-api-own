# 评估：默认范围去掉天数档、本月/上月换序

## 用户意见（2026-10-18）

截图：默认范围下拉 = `1 天 / 7 天 / 14 天 / 30 天 / 本月 ✓ / 上月`。
「我感觉这些天就没必要了，而且本月和上月的上下对换一下，你看看怎么样」

## 只读评估项

1. 偏好设置的默认范围选项来源与编码方式（`days:<n>` / `<kind>`）；
2. **若去掉天数档**：已保存的天数默认值（如 30 天）在新下拉里如何显示（悬空值风险），以及需要怎样兜底；
3. 筛选对话框的快捷范围是否也要动（1/7/14 天在那里是否还有用）；
4. 本月/上月换序的落点（偏好下拉 + 筛选按钮保持一致）；
5. 给意见：是否建议按此调整、风险与最小改法。

## 评估结论（2026-10-18，只读）

### 现状

- 偏好下拉：两个 `SelectGroup` —— 天数（`dayRangeOptions`←`TIME_RANGE_PRESETS`）+ 自然月（`monthRangeOptions`←`NATURAL_MONTH_PRESETS`）；
  取值编码 `days:<n>` 或 `<kind>`（`models-chart-preferences.tsx:70-95`）；
- 顺序来源：`NATURAL_MONTH_PRESETS = [This Month, Last Month]`（`constants.ts:80`）—— **换序只需改这一处**，
  偏好下拉与筛选对话框会同时生效（一致性 ✓）；
- 筛选对话框的快捷范围 = 天数按钮（1/7/14/30）+ 自然月按钮（两组并列，`models-filter-dialog.tsx:209,229`）。

### 意见

- **去掉默认范围里的天数档：赞成** ✓ —— "默认范围"表达的是周期口径（本月/上月），凑天数不该出现在这里；
- **上月/本月换序：赞成** ✓ —— 按时间顺序（上月 → 本月）更自然，且只需改一处常量；
- **筛选对话框的 1/7/14 天建议保留** ✓ —— 临时看"最近 7 天"仍然有用；两处不必强求完全一致。

### 风险与兜底（关键）

用户当前存的默认范围是 **30 天**（`{kind:'days', days:30}`）。若下拉里删掉天数档：
- **触发器会显示空/悬空值** ✗（`days:30` 不在 items 里）；
- 兜底做法：**打开偏好对话框时把 draft 归一化** —— 若当前 kind 是 `days`，draft 显示为「本月」（并在保存时落盘 `month-to-date`）；
  图表在用户保存前仍按旧值渲染（不静默改数据）；
- 解析层继续接受 `days`（向后兼容不破坏），只是 UI 不再提供。

## 实现结果（2026-10-18，v0.0.27）

- 偏好设置「默认范围」= **只剩两项**：`Last Month → This Month`（上月在前，与用户要求一致）；
  `NATURAL_MONTH_PRESETS` 改为 `[Last Month, This Month]` → 偏好下拉与筛选对话框月按钮同步换序；
- 偏好下拉不再生成天数项；**筛选对话框的 1/7/14/30 天按钮保留** ✓；
- **旧值兜底**：存档为天数档时对话框**显示「本月」但不写盘**，点保存才落盘 `month-to-date`；
  保存前图表仍按旧值（30 天）渲染；解析层继续接受 `days`（`{kind:'days',days:30}` → 09-19→now 不变），29→30 迁移不回归；
