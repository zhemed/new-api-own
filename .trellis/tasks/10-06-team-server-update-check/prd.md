# 服务端更新检查（后端）— PRD

## Goal

把"检查更新"从**浏览器直连 `api.github.com`** 改为**服务端检查 + 接口暴露**：内网/大陆部署不再依赖浏览器出网；
版本比较语义与前端一致；数据源可替换（等 `hunt-deploy-chain` 的调研结论接入）。

## Requirements

1. **默认关闭**：更新检查默认不开启，绝不在离线部署下擅自外呼；由环境变量/设置项开启（沿用仓库既有 env + OptionMap 机制）。
2. **开启后的健壮性**：请求带超时；结果带缓存（≥1h）；失败退避（失败后一段时间内不重试）；只取必要字段（不抓全量 release 列表/正文）；
   日志**不得**出现任何凭据/令牌（URL 里带 token 的形态一律不允许）。
3. **接口暴露**：结果通过 HTTP 接口暴露给前端，字段语义为：当前版本、最新版本（可能未知）、是否有更新（**三态**：有更新/无更新/未知）。
   在"独立端点"与"扩展 `/api/status`"之间做出选择并给出理由。
4. **版本比较**：后端实现一份与前端 `version-compare.ts` 等价的语义（去 `v` 前缀、逐段数值比较、预发布低于正式版、无法比较时为 unknown），并配单测。
5. **数据源适配点**：数据源封装为可替换接口（先按 GitHub Releases 实现，但默认关闭），便于 `hunt-deploy-chain` 结论落地时替换/新增源。
6. **测试**：开启/关闭、缓存命中、超时/网络失败（假 fetcher，禁止真实网络与真实 dialector）、版本比较边界。
7. 命令全绿：`GOWORK=off go vet ./...`、`GOWORK=off go build ./...`、`cd relaykit && GOWORK=off go build ./...`、`make test`。

## Acceptance Criteria

- [ ] 默认关闭：无配置时后端不发起任何外呼，接口返回"未知/未启用"而不是报错。
- [ ] 开启 + 假 fetcher：解析出最新版本；命中缓存不再二次调用；超时/错误不 panic、返回未知并进入退避窗口。
- [ ] 版本比较单测覆盖：`v` 前缀、段数不同（1.2 vs 1.2.0）、预发布（1.2.0-rc1 < 1.2.0）、非版本字符串 → unknown。
- [ ] 日志与响应中无凭据/令牌；错误信息不泄露 token。
- [ ] 四条命令实测通过（记录退出码）。

## Notes

- 写范围：`service/`、`common/`、`setting/`、`router/`、`controller/` 及对应 `*_test.go`。
- 红线：不 commit/push；不碰生产/3020；不实例化真实 DB dialector；不写工作区外文件；
  GitHub 只读请求仅在功能开启时发起，且必须可关闭。
- 前端 `web/**` 由另一条线负责，本任务只提供接口与语义对齐。
